Overall Architecture: MVC
DQ1: Arcanist Classes (Factory Method + Strategy)
- Note: A factory will be responsible for initial creation of base Arcanist classes
- To handle class promotion, we use strategy for Arcanist classes
- Arcanist class is thus non-abstract
- 1st Factory will create base Arcanist class object with corresponding Strategy assigned
- 2nd Factory (for promotion) will take in an Arcanist class object, and swap out with the new Strategy appropriately
- This Strategy idea enables for promotion, which is listed as a bonus feature in bonus_feats.txt
DQ2: Spectre Generation (Factory Method)
- Note: However, be cautious about inheriting from the exact same abstract Factory class used for the Arcanist. The ArcanistFactory requires a character input from the player, while the SpectreFactory requires an RNG seed and level context. Forcing them to share a base class (like an AbstractFactory) might muddy the interface. It is usually cleaner to keep them as two distinct, concrete factories.
- Spectre does not need the Strategy pattern like in Arcanist since no promotion logic required
- Thus, Spectre will be abstract and have

DQ4: Temporary Scrolls (Decorator)
- Because we can just unwrap these decorators when necessary
- Note: this can be achieved via shared_ptrs, whereby the main game has a ptr to the base Arcanist
- We have an interface ptr which points to decorators which use shared_ptrs in a chain to the base Arcanist
- Then when a level is complete, this interface ptr can be deleted, causing a chain-reaction of all decorators getting deleted
- Except for the base Arcanist object since there is always 1 ptr to it by the main Game
